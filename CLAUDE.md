# Златая цепь — заметки для работы в репозитории

- Прототип игры — один файл `index.html` (Three.js r128). Релизная low-poly версия — `zlataya_cep/zlataya_cep_final06.html` (предыдущие релизы `zlataya_cep_final01.html`–`zlataya_cep_final05.html` лежат рядом и больше не пересобираются); она собирается из прототипа командой `python3 zlataya_cep/build/build_final.py`. Прототип при этом не меняется; сам релизный файл вручную не правится — только модули в `zlataya_cep/build/`, после чего релиз пересобирается. Документы студии лежат в `zlataya_cep/docs/`. Описание уровней и управления — `README.md`, список отличий от сценария — комментарий в начале `index.html`.
- Тесты-боты лежат в `tools/tests/` (как запускать — `tools/tests/README.md`).
- Любой новый или изменённый бот сразу кладите в `tools/tests/bots/` (и при необходимости в `tools/tests/regress_list.txt`) и коммитьте вместе с изменением игры — боты не должны жить только во временных папках.
- **Проверка перед коммитом — выборочная:** `python3 tools/tests/affected.py --run`. Скрипт сам выбирает ботов по изменённым файлам (уровни прототипа — по функциям `buildXX`, модули релиза — по `tools/tests/affected_map.txt`), добавляет быструю страховку (`smoke`, `tfin_col`, `tallobj` — около минуты), пересобирает релиз и гоняет ботов на нём; без `--run` — только показывает, что и почему будет проверено. Обычно это несколько минут.
- **Полный регресс** (`LIST=tools/tests/regress_list_final.txt tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html`, около часа) — **только** когда `affected.py` пишет «НУЖЕН ПОЛНЫЙ РЕГРЕСС» (правка общего кода прототипа, модуль, влияющий на все уровни, инфраструктура ботов), перед выпуском новой версии релиза (`finalNN`) и один раз в `main` после слияния нескольких веток. Прототип целиком — `tools/tests/regress.sh`. Новый модуль релиза или файл сборки — сразу строка в `affected_map.txt` (иначе скрипт будет требовать полный регресс); новый бот уровня находится сам по `LV('id')`.
- Модули релиза живут в одной области видимости с прототипом: оборачивайте функции прототипа присваиванием (`step=function…`), но не объявляйте функций с их именами — сборка это проверяет и останавливается.
- Трейлер снимается ботами из релизной сборки: `tools/video/` (`trailer.js` — кадры, `audio.js` — звук, `encode.sh` — MP4; см. `tools/video/README.md`). Готовое видео в git не кладётся.
- Тексты игры для сценариста: документы Word и снимки — `zlataya_cep/docs/script/`, инструменты — `tools/script/` (как вносить правки в игру — прототип, `rep_*.py`, модули, озвучка — `tools/script/README.md`). Первый круг правок внесён (отчёт — `pravki_final06.md`). Сейчас у сценариста `zlataya_cep_texts_final06_v2.docx` со снимком `texts_final06_v2.json` («Новый вариант» пуст); присланный документ читает `node tools/script/read_doc.js присланный.docx zlataya_cep/docs/script/texts_final06_v2.json правки.md > правки.json` (по номерам строк, против того снимка, с которого делался документ), вносит `node tools/script/apply_edits.js правки.json zlataya_cep/docs/script/texts_final06_v2.json --rev=$(git log -1 --format=%h -- zlataya_cep/docs/script/texts_final06_v2.json) --write` (коммит снимка: по нему правка находит своё место, даже если файлы с тех пор менялись).
- Озвучка реплик (final06): каталог `zlataya_cep/build/voice/lines.json` и записи `<id>.mp3` рядом; голоса генерируются моделью Eleven v4 в Higgsfield, записи готовит `node tools/voice/fetch.js` (см. `zlataya_cep/docs/09_final06.md`). Сборка встраивает записи в релиз и останавливается, если озвученной строки нет в игре.

## Работа вдвоём (несколько аккаунтов Claude)
- Основная ветка — `main`: в неё — только через PR, из неё собирается релиз. Каждая задача — своя ветка от свежей `main` (одна задача — одна ветка, влить за день-два); долгие ветки расходятся с `main` и конфликтуют.
- В начале сессии: `git fetch origin main && git merge origin/main`. Перед PR — снова влить свежую `main`, пересобрать релиз, `python3 tools/tests/affected.py --run`; в описании PR — что проверено. Чужую ветку перед слиянием можно оценить: `python3 tools/tests/affected.py --base origin/main --to origin/<ветка>`.
- Одновременно не править один уровень (одну функцию `buildXX` в `index.html`) или один модуль — разные уровни сливаются сами. Кто над чем работает — в PR/issue.
- Разрешение конфликтов:
  - `zlataya_cep/zlataya_cep_final06.html` — вручную не сливать: `.gitattributes` оставляет вашу версию и помечает конфликт; после слияния исходников — `python3 zlataya_cep/build/build_final.py` и `git add` этого файла.
  - `zlataya_cep/build/voice/lines.json` — объединить записи обеих сторон (id уникальны по уровню: `5-1_091`, `5-B2_k01`, `p05a_hihi`); совпавший id — по смыслу. Сборка проверит, что каждая озвученная строка есть в игре. Файлы `.mp3` не конфликтуют.
  - `tools/tests/bots/tfin_col.js` (эталон коллизий `RELEASE`) — взять обе стороны и пересчитать для изменённых уровней; `regress_list*.txt` — объединить списки.
  - `CHANGELOG.md`, `README.md`, документы — оставить записи обеих сторон; крупная задача — свой документ в `zlataya_cep/docs/`.
  - `index.html` — конфликт в одной функции разбирать по смыслу, затем боты этого уровня (`affected.py` их найдёт).
- Новые id озвучки — с префиксом уровня; новый модуль — свободный номер `late_NN_*.js` (перед созданием посмотреть `main`, не занят ли номер другой веткой).
