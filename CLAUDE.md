# Златая цепь — заметки для работы в репозитории

Коротко — то, что нужно в каждой сессии. Подробности (сценарист, озвучка, трейлер, разрешение конфликтов, final07) — `zlataya_cep/docs/rabota.md`: читать, когда задача про это.

- **Начало — `MAP.md`** (устройство, движок, типовые задачи, таблицы уровней/модулей/ботов). Место в коде — `python3 tools/map.py where <уровень|имя|текст>`, читать только нужный диапазон (`sed -n 'A,Bp' | cut -c1-400`). Не читать целиком модули, `voice/lines.json`, релизные `.html`; вывод команд резать; кадры ботов — 2–3 ключевых; подагентов «изучить проект» не запускать. Новый уровень, модуль, бот, документ — `python3 tools/map.py`.
- **Код игры.** Прототип (Three.js r128) — части `proto/` (`proto/levels/<уровень>.js`, общий код мира `w2_common.js`, движок `proto/engine/`); `index.html` — их склейка, не в git. Релиз final06 собирает `python3 zlataya_cep/build/build_final.py` → `zlataya_cep/zlataya_cep_final06.html` (не в git, вручную не правится). Модули и замены уровня — `zlataya_cep/build/levels/<уровень>/` (мира — `levels/w2/`), общие — `build/`; порядок — по имени файла. Правка уровня — две папки: `proto/levels/<уровень>.js` и `build/levels/<уровень>/`. Модули — одна область видимости с прототипом: функции прототипа оборачивать присваиванием (`step=function…`), не объявлять функций с их именами (сборка проверит). final07/WebGPU заморожен — не трогать.
- **Проверка — в CI.** `python3 tools/tests/affected.py` — какие боты затронуты; весь набор (и полный регресс, когда он нужен) гоняет CI на PR по 8 машинам, итог — проверка `bots`. Локально — только новые и изменённые боты: `BOTS="бот1 бот2" tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html`; полный регресс локально не запускать. Бот — сразу в `tools/tests/bots/` и в коммит с правкой; новый модуль вне папки уровня — строка в `tools/tests/affected_map.txt`. Подробно — `tools/tests/README.md`.
- **Вики игры** — папка `wiki/` (страницы `.md`, картинки `wiki/images/`, снимки уровней — `node tools/wiki_shots.js`); после слияния в `main` workflow «Вики» переносит её в раздел Wiki. Правка механики или уровня — поправить и его страницу вики.
- **Журнал изменений** — файл на задачу: `python3 tools/changelog.py new "Заголовок"` (пункты `- …`), общий `CHANGELOG.md` не правится.
- **Экономия кредитов.** Одна задача — одна сессия (новая тема — новая сессия или `/clear`; в долгой задаче — `/compact`). Картинки (кадры роликов, снимки ботов, скриншоты) — по 1–2 ключевых, уменьшенные; серии кадров — только когда задача про ролик. Баг без шагов воспроизведения — сначала спросить, где и после чего он случается, а не перебирать гипотезы прогонами. Слежение за CI после PR не включать: автослияние сделает своё, упавший CI чинится в новой короткой сессии.

## Работа вдвоём (несколько аккаунтов Claude)
- В `main` — только через PR. Задача — своя ветка от свежей `main`. В начале сессии и перед PR: `git fetch origin main && git merge origin/main`, пересобрать релиз, прогнать новых и изменённых ботов.
- **Закончил задачу — сам, без напоминаний: пуш, PR в `main` и автослияние (merge).** «Закончил» = код, новые и изменённые боты зелёные локально, журнал, вики, `MAP.md`. Пользователь тестирует результат в `main`, поэтому PR не откладывать и разрешения не спрашивать: это постоянная просьба пользователя, она заменяет общее «PR — только по просьбе». PR вливается сам, когда `bots` зелёная; сессия не ждёт CI. Упал CI — исправить и запушить, автослияние сработает после зелёного. Без PR — только если файлы не менялись (вопрос, разбор) или пользователь прямо сказал не вливать.
- Не править одновременно один уровень или один модуль. Новый модуль — свободный номер `late_NN_*.js` (проверить `main` и чужие ветки), id озвучки — с префиксом уровня.
- Конфликты при слиянии — `zlataya_cep/docs/rabota.md` (раздел «Конфликты»): `MAP.md` — `python3 tools/map.py`, эталон коллизий — `python3 tools/tests/col_update.py <уровни>`, `lines.json` и списки ботов — объединить обе стороны.
