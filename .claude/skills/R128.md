# Three.js r128 в «Златой цепи» — поправки к сторонним навыкам

Навыки `threejs-shaders`, `threejs-lighting`, `threejs-materials` написаны под Three.js r160+, `threejs-debug-profiler` — под
проект на Vite/TypeScript. Игра — **r128** без сборщика. Примеры из навыков — справка по приёмам; код писать по правилам ниже
и проверять в r128 (`THREE.REVISION` в консоли — `"128"`).

## Подключение и код
- `THREE` — глобальный объект из `three.min.js` r128 (`proto/head.html`, копия — `zlataya_cep/build/three.r128.min.js`).
  Никаких `import`, `three/addons`, `examples/jsm`; дополнения (`EffectComposer`, `RGBELoader`, `RectAreaLightUniformsLib`,
  `BufferGeometryUtils`, `ContactShadows`…) в игре **не подключены** — нужен приём из них, пишем свой небольшой код.
- Код — части `proto/` и модули `zlataya_cep/build/…` в одной области видимости (`CLAUDE.md`, `MAP.md`). Отдельных
  `.glsl`-файлов нет: шейдеры — строки в модуле.
- WebGPU, TSL, `NodeMaterial` — нет (final07/WebGPU заморожен, не трогать).

## Цвет и свет (главные расхождения с r152+/r155+)
- Цвет: `renderer.outputEncoding` / `texture.encoding` (`THREE.sRGBEncoding`), а **не** `outputColorSpace` / `colorSpace`.
  Управления цветом (`ColorManagement`) в r128 нет — цвета в `Color(…)` берутся как есть.
- Свет — старые единицы (`physicallyCorrectLights` выключено, `useLegacyLights` в r128 нет). У `PointLight`/`SpotLight` затухание
  по умолчанию `decay = 1` (с r155 — 2), интенсивности из примеров r155+ (с множителем π, в канделах) здесь не годятся —
  подбирать по кадру. Тени — `PCFShadowMap` (`proto/engine/02_render_heroes.js`).
- Свойства материалов новее r128 не работают: `iridescence*`, `anisotropy*`, `sheenColor`/`sheenRoughness` (в r128 — одно
  свойство `sheen` типа `Color`), `specularIntensity`/`specularColor`, `attenuationColor`, `thickness` и т. п.; `transmission`,
  `clearcoat` есть. Сомнение — `grep` по `zlataya_cep/build/three.r128.min.js`.

## Шейдеры
- `ShaderMaterial`/`RawShaderMaterial` работают как в навыке; GLSL 3 — `glslVersion: THREE.GLSL3` (иначе GLSL 1 с автозаменой).
- `onBeforeCompile`: имена кусков `ShaderChunk` в r128 другие — вместо `colorspace_fragment` здесь `encodings_fragment`,
  кусков `output_fragment`/`opaque_fragment` нет: итог цвета — строка `gl_FragColor = vec4( outgoingLight, diffuseColor.a );`
  прямо в шаблоне. Строку замены брать из `THREE.ShaderChunk` / `THREE.ShaderLib` r128, а не из навыка: не нашлась — эффект молча пропадёт.

## Отладка и производительность
- Нет Vite, dev-сервера и «production preview»: проверяется релиз `zlataya_cep/zlataya_cep_final06.html`
  (`python3 zlataya_cep/build/build_final.py`). Воспроизведение и замеры — ботами (`tools/tests/README.md`, `run_one.sh`),
  снимки — `tools/tests/shot.js`; `renderer.info` доступен из бота через глобальный рендерер игры.
- Ссылки навыка на «lead», `threejs-3d-generator`, `smart_low_poly`, glTF/Draco и `__THREE_GAME_DIAGNOSTICS__` к проекту не относятся
  (модели процедурные, ассетов glTF нет).
- Приёмы по выигрышу те же: `InstancedMesh` (в игре уже ~30 мест), общие геометрии и материалы, пулы эффектов, отсечение, предел DPR,
  дешёвые тени.
