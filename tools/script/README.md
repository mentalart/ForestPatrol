# Тексты игры для сценариста

Все тексты «Златой цепи», которые видит или слышит игрок, — в документе Word для сценариста, и его правки — обратно в игру.
В документ входят реплики и ремарки роликов, реплики в игре, задачи, подсказки, крупные надписи, надписи над героями и в мире,
названия уровней, строки паузы «Что мы делаем», Сказы и сказки Кота; в приложениях — имена персонажей, помощники и предметы,
лавка Векши, надписи интерфейса в игре. Меню, настройки, титры, сохранения и отладка не входят.

Документы и снимки лежат в `zlataya_cep/docs/script/`:
- **сейчас у сценариста — `zlataya_cep_texts_final06_v2.docx`** (снимок `texts_final06_v2.json`): все тексты игры после первого
  круга правок, включая новые места (обучение и этапы финала 5-Б2, сценка с самокатом в прологе, переделанный 5-1);
  «Новый вариант» пустой. Присланный с правками документ читать против `texts_final06_v2.json` без `--proposals`;
- круг 1: `zlataya_cep_texts_final06.docx` (снимок `texts_final06.json`, в «Новом варианте» — стихотворные варианты в духе сказок
  Пушкина из `verse_final06.json`), присланный сценаристом `zlataya_cep_texts_final06_fix.docx`, прочитанные правки
  `pravki_final06.json` и отчёт `pravki_final06.md` — что внесено, что нет и почему;
- снимок (`texts_*.json`) — каждая строка документа по номеру, её текст и **все места в исходниках**, откуда она берётся.

## Инструменты
Один раз: `cd tools/script && npm i` (acorn, docx, jszip).

```
node tools/script/extract.js [релиз.html] > тексты.json                  # все тексты релиза (по умолчанию final06)
node tools/script/make_doc.js тексты.json документ.docx [предложения.json]  # документ Word (с предложениями — «Новый вариант» заполнен)
node tools/script/read_doc.js документ.docx тексты.json правки.md [--proposals=предложения.json] > правки.json   # правки сценариста
node tools/script/apply_edits.js правки.json тексты.json --rev=<коммит снимка> [--write] > отчёт.json      # правки — в исходники
```

- **extract.js** разбирает код релизной сборки (acorn) и находит каждую строку с русским текстом. Текст, собранный в коде,
  показывается целиком: вставки игры — `{кнопка «прыжок»}`, `{имя героя}`, `{число}`, `{вставка}`; условия `a?'x':'y'` —
  отдельными вариантами («вариант 1 из 2», условие — если простое). Составные строки интерфейса (много вариантов и вставок)
  — по кускам («часть составной строки»). Одинаковые тексты в разделе — одна строка («встречается N раз»). Для каждой строки:
  раздел (уровень), ролик и время в нём (`says` в `play()`), кто говорит (вызов `say`/`bark`/`sayP`, пара `[кто, текст]`,
  место использования списка строк, каталог озвучки), озвучена ли (`build/voice/lines.json`), и `occ` — все места: файл, строка
  и сам литерал в кавычках (`raw`) для каждого куска. Файл — `index.html` (прототип), `zlataya_cep/build/late_*.js` (модуль
  релиза) или `zlataya_cep/build/rep_*.py` (замена сборки: текст релиза отличается от прототипа). Названия роликов — из
  таблицы `zlataya_cep/docs/05_cinematics.md`. Что не входит — `SKIP_MODS`, `SKIP_TOP`, `SKIP_TEXT` в начале файла.
- **make_doc.js** пишет A4 альбомную таблицу: № · Кто / что · Сейчас в игре · Новый вариант · Комментарий; вступление —
  как править, обозначения, для кого пишем, виды текстов, персонажи (характер — из `cast` каталога озвучки), содержание.
  Разметка: `<i>` — курсив (ремарка), `<b>` — жирный, `<br>` — перенос, `{…}` — серый фон.
- **read_doc.js** находит столбцы по заголовкам и сравнивает строки со снимком по номеру. Виды правок: `edit` (новый вариант
  или исправление прямо в «Сейчас в игре»), `delete` («УДАЛИТЬ»), `add` (строка без номера — после строки `after`), `note`
  (только комментарий), `lost` (строки нет в документе). Режим исправлений Word — вставки учитываются, удаления нет;
  примечания Word попадают в комментарий. Курсив и жирный из документа — `<i>`/`<b>`. Нетронутый документ даёт 0 правок;
  проверено и после пересохранения документа в LibreOffice. С `--proposals` у каждой правки `edit` видно, принято ли
  предложение как есть (`accepted`) или сценарист его исправил (`changed`); `declined` — предложение стёрто, текст остаётся.
  Нетронутый документ с предложениями читается как 2075 правок `accepted`.
- **apply_edits.js** раскладывает правки `edit` по исходникам: новый текст делится по вставкам игры `{…}`, куски меняются в тех же
  кавычках (в `rep_*.py` — правая строка замены), значки и атрибуты тегов возвращаются из старой строки (**markup.js**), пробелы
  у вставок — как в новом тексте. Место куска в нынешнем файле ищется по коду вокруг него в версии `--rev` (коммит, с которого
  делался снимок), поэтому файлы могли меняться после снимка. Без `--write` только отчёт: `applied` (что заменится) и `problems`
  (что сделать руками: конфликт двух правок в одном месте, кусок собран из нескольких строк, текста больше нет). Снимок для
  `apply_edits` должен быть сделан тем же `extract.js` (поля `order` и `col`).
- **extract.js** пропускает функции прототипа, которые модуль релиза заменяет целиком (`name=function…` без сохранения прежней,
  например `build5B2` — финал 5-Б2 теперь в `late_93`): в релизе они не работают. Одинаковые строки в функциях-двойниках
  привязываются к своему месту по порядку появления, модули со своим разделом — таблица `MODLV`.

## Как внести правки сценариста
1. Положить присланный документ в `zlataya_cep/docs/script/` и прочитать правки **против того снимка, с которого делался
   документ** (дата снимка — на первой странице и в свойствах документа):
   `node tools/script/read_doc.js присланный.docx zlataya_cep/docs/script/texts_final06.json zlataya_cep/docs/script/правки.md --proposals=zlataya_cep/docs/script/verse_final06.json > правки.json`.
   Заполненный «Новый вариант» — это правка: оставленное как есть стихотворное предложение тоже меняет текст в игре.
   Показать пользователю сводку (сколько предложений принято, исправлено, стёрто); неясное (новые строки, «поменять везде»,
   правки, меняющие смысл механики, заметно удлинённые реплики роликов) — уточнить.
2. `node tools/script/apply_edits.js правки.json снимок.json --rev=<коммит снимка>` — посмотреть отчёт, затем с `--write`; места
   из `problems` — руками. Каждая правка `edit`: в `occ` — все места этого текста. В каждом месте найти литерал `raw` (строка
   файла — подсказка: если файл менялся после снимка, искать по самому `raw`) и заменить текст:
   - один кусок без вставок — заменить литерал целиком (кавычки те же, `'` внутри — `\'`; курсив — `<i>…</i>`);
   - несколько кусков со вставками `{…}` — разрезать новый текст по вставкам и поменять куски по порядку; вставки
     переставлены или убраны — поправить само выражение в коде;
   - файл `rep_20_subs.py` / `rep_30_gameplay.py` — менять **правую** (новую) строку замены, прототип не трогать;
   - файл `index.html` — менять прототип (релиз соберётся из него); `late_*.js` — модуль.
   Тот же текст в других местах (например, копии Сказов в `startFrom`, копия финала в модуле) — поискать `grep` по старому
   тексту и поправить тоже. Проверка: `extract.js` новой сборки и сравнение со снимком — у каждой строки с правкой в игре
   должен быть новый текст, у остальных — прежний (что пропало — удалено или переписано в коде после снимка).
3. `delete` — убрать вызов (реплику из `says`, `say(…)`, подсказку) так, чтобы логика не сломалась; `add` — новая реплика:
   в ролик — новая запись `says` со временем между соседними, в игру — рядом с соседней репликой.
4. Озвученные строки (`voice` в снимке): в `zlataya_cep/build/voice/lines.json` у этих id поменять `text` (точно как в
   игре; у собранных из кусков — и `parts`), `tts` (подсказки интонации в квадратных скобках оставить, `<br>` — пробел),
   убрать `url`, `job`, `dur`; сгенерировать голос в Higgsfield (`elevenlabs_v4`, голос из `cast`) и `node tools/voice/fetch.js`
   — см. `zlataya_cep/docs/09_final06.md`. Если одну запись делили две строки, а правки их развели, — вторая строка становится
   новой репликой (`tools/voice/extract.js` + `plan.js` добавят её в каталог). Сборка останавливается, если озвученной строки
   нет в игре, — это проверка, что текст и каталог совпали. Списки реплик «из данных» (начала и концы Сказов, пирожки,
   счёт рыбки) — вручную в конце `tools/voice/extract.js`, их тоже поправить.
5. Боты могут проверять тексты: `grep -rn 'старый текст' tools/tests/bots` и поправить вместе с игрой.
6. `python3 zlataya_cep/build/build_final.py`, бот `tfin_voice`, затем релизный регресс
   (`LIST=tools/tests/regress_list_final.txt tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html`).
7. Новый снимок и документ для следующего круга: `extract.js` → `texts_<дата или версия>.json`, `make_doc.js` → `.docx`.
