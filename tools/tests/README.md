# Тесты-боты «Златой цепи»

Боты открывают `index.html` в Chromium через Playwright, нажимают клавиши за обоих игроков (или за одного — в одиночном режиме) и проходят уровни: ковка, бои, ритм-сцены, ролики, хаб. Каждый бот печатает, что получилось, и при желании снимает кадры.

## Что нужно
- Node.js 18+ и Python 3.
- Playwright с Chromium: `npm i -D playwright && npx playwright install chromium` (подойдёт и глобальная установка).
- Интернет не нужен: Three.js r128 лежит в `vendor/three.min.js` и подставляется вместо CDN.

## Какие боты гонять — выборочный регресс
Полный регресс — больше сотни ботов, а правка обычно затрагивает один уровень или модуль. `affected.py` выбирает ботов по изменённым файлам:
```sh
python3 tools/tests/affected.py          # что изменилось с ответвления от origin/main и какие боты это проверяют (ничего не запускает)
python3 tools/tests/affected.py --run    # пересобрать релиз и прогнать выбранных ботов (JOBS — --jobs, по умолчанию 2) — это делает CI на PR;
                                        # --shard I/N — только доля I из N (CI делит набор на 8 машин, итог — проверка «bots»);
                                        # --full-ci — нужен полный регресс: прогнать весь regress_list_final.txt (CI), --all — без разбора правок
python3 tools/tests/affected.py --base HEAD --run                    # только незакоммиченные правки
python3 tools/tests/affected.py --base origin/main --to origin/ветка # оценить чужую ветку перед слиянием
```
- **прототип** (части `proto/`, склеенные в `index.html`) — по изменённым строкам склейки: функция уровня (`buildXX` из таблицы `LEVELS`) → боты этого уровня (бот уровня находится сам — по
  `LV('id')`, `loadLevel(N)`, `U.go()` для пролога); общая функция, которую вызывают только функции уровней, → эти уровни; общий код
  (главный цикл, герои, враги, таблицы вне функций) → полный регресс. Комментарии и пустые строки не считаются.
- **Остальные файлы** — по таблице `affected_map.txt`: имена ботов, `@level:<id>` (все боты уровня), `@wide` (всё, что рисует мир на всех
  уровнях: арт, пачки, бюджет, видимость, враги, персонажи), `@full`, `-` (документы, инструменты вне игры). Для `rep_*.py` — по разделам
  `# ---- …`. Файла нет в таблице — полный регресс: новый модуль сразу допишите в таблицу.
- К любой правке кода игры добавляется страховка: `smoke` (все уровни грузятся и играются), `tfin_col` (коллизии всех уровней), `tallobj`
  (задачи всех уровней) — вместе около минуты.
- Полный регресс гоняет CI (на PR — сам, если скрипт пишет «НУЖЕН ПОЛНЫЙ РЕГРЕСС»; ночью на `main`; вручную — Actions → «Боты» → Run workflow), локально — не нужен. Раньше — только если скрипт пишет «НУЖЕН ПОЛНЫЙ РЕГРЕСС», перед выпуском новой версии релиза и один раз в `main` после слияния
- Бюджет отрисовок (`tfin_budget`) в основном прогоне идёт в низком качестве — без теней. Ночью и при ручном «полном регрессе» отдельная работа `budget-hq` (`.github/workflows/bots.yml`) гоняет его ещё раз с `URLQ='&hq=1'` — с тенями, как играют по умолчанию; локально — `URLQ='&hq=1' tools/tests/run_one.sh tfin_budget zlataya_cep/zlataya_cep_final06.html`.
  нескольких веток.

## Запуск
```sh
tools/tests/run_one.sh t41v zlataya_cep/zlataya_cep_final06.html   # один бот на релизе (без пути — на прототипе ./index.html)
JOBS=4 tools/tests/regress.sh            # больше потоков (на 4 ядрах лучше 2–3: иначе тяжёлые боты упираются в таймаут 900 с)
BOTS="t41v tfin_col" tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html   # свой набор
# полный регресс — только релиз (прототип index.html — исходник релиза, его отдельно не гоняют)
LIST=tools/tests/regress_list_final.txt tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html
```
В релизной сборке отладочный объект `window.ZC` есть только с параметром `?debug` — запускалка передаёт его сама. В этом режиме графика по умолчанию низкая (так боты идут быстрее); для снимков в высоком качестве задайте `URLQ='&hq=1'`. В headless-браузере CSS-переходы и сглаживание по реальному времени почти не идут (кадры в JS мгновенные, растеризация отложена), поэтому боты final04 задают фиксированный шаг: `ZC.FIN.occ.fdt`, `ZC.FIN.cam.fdt`, а для карточек отключают переходы.
Снимки шагов (`shot=`) — материал для разбора, не проверка: не успел за `SHOT_TIMEOUT` мс (по умолчанию 45000; на CI с программной
графикой бывает) — в выводе `SHOT SKIPPED`, бот идёт дальше.

`regress.sh`: `SHARD=I/N` — доля списка; бот, упавший не из-за игры (код 124 — таймаут `BOT_TIMEOUT`, по умолчанию 900 с; 127, 137, 139; закрытый браузер), повторяется один раз (`RETRY=0` — без повтора), прошёл со второго раза — `~~`; итог по ботам — `out/results.tsv` (бот, код, ошибок, секунд, код первой попытки). Сводка прогона CI — `python3 tools/tests/flaky.py --summary папка_вложений`, неустойчивые боты за 14 дней — `python3 tools/tests/flaky.py` (нужен `gh`), самые долгие — `flaky.py --times папка`. Эталон коллизий: `python3 tools/tests/col_update.py <уровни>`. Предел времени тяжёлого бота — строка `// @timeout=1800` в его файле; `STEP_TIMES=1` — время каждого шага (код, ожидание, снимок), `NOSHOTS=1` — без снимков кадров (так в CI: снимок в программной графике стоит 20–45 с). Вывод каждого бота — `out/out_<бот>.txt`, время — `out/times.txt`, кадры — `shots/` (обе папки не в git). В конце `regress.sh` печатает сводку: код возврата, число ошибок страницы (`EVAL ERROR`, `PAGEERROR`) и последний результат каждого бота (последнюю строку `> …`); строки с ошибками помечены `!!`.

Большинство ботов не проверяет ожидания жёстко, а печатает результат. Смотрите на последнюю строку: `["luko",true,…]` или `lvl=luko` — уровень пройден и игра вернулась на Лукоморье; `tallobj` — `errors=0`; `smoke` — все уровни `ok`.

## Устройство
- `bots/*.js` — сценарии. Шаги разделяются строками `//@@`, у строки можно указать `shot=имя.png` (кадр после шага), `wait=мс` (пауза после шага), `reload=1` (перезагрузить страницу перед шагом — например, проверить сохранения), `mouse=x,y` (перед шагом поставить курсор мыши в точку окна — например, над панелью паузы) и `key=Код` (перед кодом шага настоящее нажатие клавиши через Playwright, `KeyboardEvent.code` — например, первое нажатие, которое разрешает звук). Код шага выполняется в странице, возвращённое значение печатается.
- `helpers.js` — подключается первым шагом ко всем ботам: `U.go`, `U.until(cond,сек)`, `U.tap(key)`, `U.act(pi)`, `U.walkTo(pi,x,z,сек)`, `U.path(pi,[[x,z]…],сек)`, `U.st()`, `U.obj()`, `U.fight`, `U.brawl(сек)`.
- `layout_check.js` — вёрстка главного меню, «Глав» и «Настроек» на 13 размерах окна (`node tools/tests/layout_check.js [html]`, по умолчанию — final06): логотип не наезжает на пункты, пункты не обрезаются.
- `mk.py` — собирает сценарий в шаги JSON; `run.js` — прогоняет шаги в браузере; `shot.js` — один кадр страницы; `grid.js` — склейка кадров по два в ряд; `pw.js` — поиск Playwright.
- В странице боты пользуются отладочным объектом `window.ZC` из `index.html`: `ZC.startFrom(ZC.LV('4-1'))`, `ZC.tick(n)`, `ZC.press(code)`, `ZC.hold(code,on)`, `ZC.skip()`, `ZC.W`, `ZC.G`, `ZC.HERO`, `ZC.players`, `ZC.setSolo(on)`, `ZC.menuKey(code)`; в релизной сборке ещё `ZC.FIN` — меню, сохранения, настройки, музыка. В релизной сборке `window.ZC` нужно убрать — тогда боты работают только с отладочной сборкой.

## Помощники, телепорт, кадры роликов
- **Общие помощники** — `helpers.js` (`U.*`, есть в каждом боте): `U.K[pi]` — клавиши игрока, `U.step/U.goto` — к точке, `U.def(pi,i)` — щит в последний
  миг, кувырок от красного замаха, удар по миньону рядом, `U.hit(pi,e,i)` — бить врага сбоку, `U.cine()`/`U.nocine()` — ролики,
  `U.toKind(kind[,pi])` — смена героя (в одиночке — Q по кругу), `U.me()`/`U.hero(pi)`, `U.swim`, мир 2: `U.playHold(pi,ракушка,[x,z])` — сыграть и
  уступить (оставленный держит напев), `U.held(ракушка)`. Новый бот — на них (пример — `tfin_k2bbosssolo`), не переписывать заново.
- **Телепорт** — `ZC.FIN.warp(n)` к n-му колокольчику любого уровня, `ZC.FIN.warp('имя')` — к участку уровня, где он назван (2-1…2-Б: `warpNN`),
  `ZC.FIN.warp(x,z)` — в точку, `ZC.FIN.warpList()` — что есть (модуль `late_95b_warp.js`, бот `tfin_warp`). На 1-4, 4-1, 5-1 сюжет уровня
  может сразу переставить героев сам.
- **Кадры ролика** — по кадру на каждый план, с репликой в субтитрах: `node tools/tests/cine_frames.js 1-1 --code "…"` (или `--nth N`,
  `--warp …`, `--solo`); кадры — `shots/cine/`. Сперва `build_final.py`.
- **Архив** — `bots/archive/`: ранние и отладочные боты, которых нет в списках (их и раньше не гоняли).

## Новый бот
1. Скопируйте похожий бот из `bots/` (лучше — на помощниках `U.*`), поправьте шаги.
2. `tools/tests/run_one.sh имя` — проверьте вывод и кадры в `shots/`.
3. Если бот должен входить в полный регресс — допишите имя в `regress_list_final.txt`; запускайте его на релизе.
4. Закоммитьте его вместе с изменением игры.
