# Тесты-боты «Златой цепи»

Боты открывают `index.html` в Chromium через Playwright, нажимают клавиши за обоих игроков (или за одного — в одиночном режиме) и проходят уровни: ковка, бои, ритм-сцены, ролики, хаб. Каждый бот печатает, что получилось, и при желании снимает кадры.

## Что нужно
- Node.js 18+ и Python 3.
- Playwright с Chromium: `npm i -D playwright && npx playwright install chromium` (подойдёт и глобальная установка).
- Интернет не нужен: Three.js r128 лежит в `vendor/three.min.js` и подставляется вместо CDN.

## Запуск
```sh
tools/tests/run_one.sh t41v              # один бот (по умолчанию — ./index.html)
tools/tests/run_one.sh t41v путь/к/index.html
tools/tests/regress.sh                   # полный регресс по regress_list.txt, 3 потока
JOBS=4 tools/tests/regress.sh            # больше потоков
# релизная сборка: все боты прототипа + боты титула, меню и сохранений
LIST=tools/tests/regress_list_final.txt tools/tests/regress.sh zlataya_cep/zlataya_cep_final05.html
```
В релизной сборке отладочный объект `window.ZC` есть только с параметром `?debug` — запускалка передаёт его сама. В этом режиме графика по умолчанию низкая (так боты идут быстрее); для снимков в высоком качестве задайте `URLQ='&hq=1'`. В headless-браузере CSS-переходы и сглаживание по реальному времени почти не идут (кадры в JS мгновенные, растеризация отложена), поэтому боты final04 задают фиксированный шаг: `ZC.FIN.occ.fdt`, `ZC.FIN.cam.fdt`, а для карточек отключают переходы.
Полный регресс идёт около получаса. Вывод каждого бота — `out/out_<бот>.txt`, кадры — `shots/` (обе папки не в git). В конце `regress.sh` печатает сводку: код возврата, число ошибок страницы (`EVAL ERROR`, `PAGEERROR`) и последний результат каждого бота (последнюю строку `> …`); строки с ошибками помечены `!!`.

Большинство ботов не проверяет ожидания жёстко, а печатает результат. Смотрите на последнюю строку: `["luko",true,…]` или `lvl=luko` — уровень пройден и игра вернулась на Лукоморье; `tallobj` — `errors=0`; `smoke` — все уровни `ok`.

## Устройство
- `bots/*.js` — сценарии. Шаги разделяются строками `//@@`, у строки можно указать `shot=имя.png` (кадр после шага), `wait=мс` (пауза после шага) и `reload=1` (перезагрузить страницу перед шагом — например, проверить сохранения). Код шага выполняется в странице, возвращённое значение печатается.
- `helpers.js` — подключается первым шагом ко всем ботам: `U.go`, `U.until(cond,сек)`, `U.tap(key)`, `U.act(pi)`, `U.walkTo(pi,x,z,сек)`, `U.path(pi,[[x,z]…],сек)`, `U.st()`, `U.obj()`, `U.fight`, `U.brawl(сек)`.
- `layout_check.js` — вёрстка главного меню, «Глав» и «Настроек» на 13 размерах окна (`node tools/tests/layout_check.js [html]`, по умолчанию — final05): логотип не наезжает на пункты, пункты не обрезаются.
- `mk.py` — собирает сценарий в шаги JSON; `run.js` — прогоняет шаги в браузере; `shot.js` — один кадр страницы; `grid.js` — склейка кадров по два в ряд; `pw.js` — поиск Playwright.
- В странице боты пользуются отладочным объектом `window.ZC` из `index.html`: `ZC.startFrom(ZC.LV('4-1'))`, `ZC.tick(n)`, `ZC.press(code)`, `ZC.hold(code,on)`, `ZC.skip()`, `ZC.W`, `ZC.G`, `ZC.HERO`, `ZC.players`, `ZC.setSolo(on)`, `ZC.menuKey(code)`; в релизной сборке ещё `ZC.FIN` — меню, сохранения, настройки, музыка. В релизной сборке `window.ZC` нужно убрать — тогда боты работают только с отладочной сборкой.

## Какие боты что проверяют
- `regress_list_final.txt` — регресс релизной сборки: то же плюс `tfin_menu` (заставка, титул, меню, режим, пауза, выход в меню) `tfin_save` (сохранение после уровня, «Продолжить» после перезагрузки, главы, настройки) `tfin_dev` (Ctrl+Alt+] — все уровни открыты, Ctrl+Alt+[ — всё стёрто и чистый запуск) `tfin_splash` (заставка студии: кадры по времени через `FIN.splashSeek`, выход в титул, пропуск клавишей) `tfin_cine` (кино final02: вход в ролик, наезды на говорящих, длина ролика при slow-mo, выход, пропуск, постановка пролога, герои на земле), `tfin_col` (final03: хеш коллизий, триггеров, спавнов и падения по всем уровням совпадает с прототипом; эталон снят с `index.html` и вписан в бота) `tfin_art` (final03: герои-скелеты — две ноги Потапа, лицо, треугольники, призрак; ходьба; стилизация, одевание мира, тропинка, scatter, пачки статики, вода, море, небо, лава), `tfin_boss4b` (final04: обучающие ролики 4-Б — карточки, ожидание нажатий, авто-показ за 8 с, восстановление голов и узды, подсказки в бою и «Молодец!», короткое напоминание, пропуск), `tfin_occ` (final04: видимость героя за стеной по пикселям — без системы и с вырезом и силуэтом, пол под стеной и то, что за героем, не меняются, затухание у камеры, живое без выреза, «прозрачные стены» узором) `tfin_cam` (final04: камера правым стиком — дефолт не меняется, мёртвая зона, отклик, инерция, пределы, инверсия, ходьба относительно камеры, сплит, автовозврат, столкновения); final05: `tfin_pads` (два джойстика в меню: навигация, назад, Start закрывает паузу, появление по очереди и «дребезг», подменю, соло, «шляпка»), `tfin_downswap` (играть вторым героем, пока первый без сил; друг поднимает; таймер; соло — любой живой), `tfin_foekinds`, `tfin_foekinds2`, `tfin_foekinds3` (все 28 видов врагов, по 8–10 на бота, видны в драке: разница кадров и треугольники), `tfin_foeidle` (враг, появившийся позже и постоявший вдали, не склеен в статику и виден), `tfin_slash` (удар героев — кадры, в том числе в свете пера; с `URLQ='&hq=1'`), `tfin_budget` (бюджет отрисовок по всем уровням: общий экран ≤ 600, два экрана ≤ 900; замер — с `URLQ='&hq=1'`), `tfin_fadebatch` (пачки «прозрачных стен»: растворение по номеру стены, сосед не трогается, сдвинутая стена выходит из пачки), `tfin_cast` и `tfin_foecast` (витрины персонажей и врагов: скелет, лицо, API, новые облики). Отдельно, не в списке: `tfin_foevis` — враги на всех уровнях и аренах (около часа).
- `regress_list.txt` — полный регресс прототипа: пролог, все миры, боссы, хаб, эпилог, Застава, задачи всех уровней (`tallobj`) и одиночный режим (`tsolo`, `tsolo41`, `tsospot`, `tso13`, `tso33`, `tso54`).
- Остальные файлы в `bots/` — ранние версии и отладочные боты (`*dbg*`, `art*`, варианты вроде `t13b`, `t22c`, `t33d`). Они остались как заготовки; часть из них написана под старые версии уровней и может не проходить.

## Новый бот
1. Скопируйте похожий бот из `bots/`, поправьте шаги.
2. `tools/tests/run_one.sh имя` — проверьте вывод и кадры в `shots/`.
3. Если бот должен входить в полный регресс — допишите имя в `regress_list.txt`.
4. Закоммитьте его вместе с изменением игры.
