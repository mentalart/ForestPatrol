## Этап 1 — безопасность (2026-10-07)

Игра клиентская (один файл, офлайн; на Pages — тот же код + озвучка отдельными файлами), серверной части и учётных записей нет. Поэтому реальные риски — это то, что приходит снаружи в браузер игрока (URL, `localStorage`), и цепочка сборки/CI.

Как воспроизводилось: сценарии с испорченным `localStorage` в Chromium по релизу final06 (15 вариантов: сохранение, настройки, гардероб, `__proto__`), затем бот `tsec_storage` — на исходном коде падает (`Cannot create property 'proshka' on string 'x'`), после правок проходит.

### Проверено, находок нет

- **`eval`, `new Function`, `document.write`, строковые `setTimeout`** — в игре нет (`eval` только в `tools/video/trailer.js`: сценарий съёмки из локального файла).
- **`postMessage`, `location.hash`, cookie** — не используются; из URL читаются только `?debug` и `?hq` (проверка регуляркой).
- **`innerHTML`** — около 70 присваиваний: везде собираются константы игры (`W.name`, `W.sub`, `W.pauseLine`, названия боссов, фазы) и числа. Строк из URL или `localStorage` среди них нет: `saveSummary` строит текст из чисел и названий уровней.
- **`window.ZC` / отладка** — в релизе без `?debug` объекта нет (`build_final.py:86`; проверено в Chromium: `typeof window.ZC === 'undefined'`, в `window` нет `G`, `W`, `FIN`, `players`…). С `?debug` доступны все читы — это сознательно и для одиночной игры без рейтингов безопасности не касается.
- **Загрязнение прототипа** через `__proto__` в сохранении и настройках не воспроизводится (поля сохранения — белый список `SAVE_FIELDS`, `({}).polluted` не появляется).
- **Внешние ресурсы** — релиз встраивает three r128 (`build_final.py:50`), CDN нет; единственный `fetch` — озвучка на Pages по константным относительным путям. `proto/head.html` (прототип `index.html`, не в git и не публикуется) подключает three с cdnjs без SRI — только для разработки.
- **Секреты** — `git grep` по отслеживаемым файлам и `git log -G` по всей истории (188 коммитов): ключей, токенов, приватных ключей нет. Это поиск по шаблонам, не полноценный сканер.
- **Зависимости** — `npm audit` по `tools/script` и `tools/voice`: 0 уязвимостей. `tools/three` (final07, заморожен) без lock-файла — не проверялся.
- **Остальные workflow** — `flaky.yml` с узкими правами; в `preview.yml` и `release.yml` сообщение коммита идёт через `env`, не подставляется в `run:`; сторонних actions нет, только `actions/*`.

### Не менялось: решения владельца

| id | где | суть и предложение |
|---|---|---|
| R1 | `build/late_95_dev.js` | **Ctrl+Alt+[ (в русской раскладке — «х») стирает все сохранения, настройки и гардероб без подтверждения** и доступно любому игроку в релизе (Ctrl+Alt+] открывает все уровни). Если это не только для разработки — подтверждение вторым нажатием в течение 3 с. |
| R2 | Pages | `localStorage` привязан к origin, а не к пути: на `mentalart.github.io` любой другой проект того же аккаунта читает и пишет ключи `zlatayaCep.*` (S1-01…S1-03 как раз про такие записи). Решение — отдельный домен или поддомен. |
| R3 | `head.html` | Нет CSP (`<meta http-equiv="Content-Security-Policy">`). Приёмников инъекций не найдено, выигрыш мал, а риск сломать озвучку и шрифты на Pages и `file://` реален. Если нужен — отдельная задача с проверкой нарушений CSP во всех ботах. |
| R4 | `release.yml` | Права `contents`, `pages`, `id-token: write` выданы на весь workflow, в том числе задаче сборки. Верно разнести по задачам; не менялось, потому что запускается только после слияния в `main` и заранее не проверить. |
| R5 | `bots.yml` | `npm i -g playwright` без версии: новая версия может изменить или уронить CI (надёжность, не безопасность). Предложение — зафиксировать версию. |
| R6 | `wiki.yml` | Токен в URL клонирования вики (`x-access-token:…@github.com`) — в логах маскируется, риск низкий; можно заменить на `http.extraheader`. |
