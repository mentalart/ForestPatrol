# Работа в репозитории — подробности

Вынесено из `CLAUDE.md`, чтобы он был коротким (его читает каждая сессия). Здесь — то, что нужно по случаю.

## Сборка и выкладка

- Собранный релиз в git не хранится (`.gitignore`): в новой сессии его собирает хук старта (`.claude/hooks/session-start.sh`) или `python3 zlataya_cep/build/build_final.py`. Предыдущие релизы `final01`–`final05` больше не пересобираются.
- После каждого слияния в `main` `.github/workflows/release.yml` выкладывает игру: GitHub Pages (https://mentalart.github.io/ForestPatrol/ — лёгкая версия, голоса отдельными файлами: `build_final.py --pages`) и Releases (цельный файл, последние 50 версий).
- **final07** (WebGPU, Three r186) снят: грузился дольше и местами тормозил — актуальный релиз final06. Слой `zlataya_cep/build/gpu/` и `build_final.py --gpu` заморожены: не собирать, шейдеры для WebGPU не переводить, ботов final07 не гонять (`docs/18_webgpu.md` — для истории).
- Описание уровней и управления — `README.md`, список отличий от сценария — комментарий в начале `proto/head.html`. Документы студии — `zlataya_cep/docs/`.

## Проверка (подробно)

- **Проверка — выборочная, и гоняет её CI.** `python3 tools/tests/affected.py` показывает, каких ботов затрагивает правка (уровни прототипа — по функциям `buildXX`, модули релиза — по `tools/tests/affected_map.txt`, плюс страховка `smoke`, `tfin_col`, `tallobj`). Весь этот набор прогоняет CI на каждом PR — на восьми машинах (`--shard I/8`), итог — проверка `bots` (в её отчёте Summary — таблица: упавшие, прошедшие со второго раза, самые долгие); в `main` — только после её зелёного. Локально (после `python3 zlataya_cep/build/build_final.py`) — только новые и изменённые боты: `BOTS="бот1 бот2" tools/tests/regress.sh zlataya_cep/zlataya_cep_final06.html` (и страховку, если правка рискованная); `affected.py --run` целиком локально не дублировать.
- **Полный регресс гоняет CI, локально его не запускать** (в сессии он шёл больше двух часов и падал от перегрузки машины). Когда `affected.py` пишет «НУЖЕН ПОЛНЫЙ РЕГРЕСС» (правка общего кода прототипа, модуль на все уровни, инфраструктура ботов), CI на PR сам гоняет весь `regress_list_final.txt` по 8 машинам (`--full-ci`, ~20 мин); ещё — каждую ночь на `main` и вручную (Actions → «Боты» → Run workflow, «полный регресс»; перед выпуском `finalNN`). Сессия читает только итог проверки `bots`. Бот, упавший не из-за игры (таймаут, закрытый браузер), повторяется один раз; прошёл со второго раза — помечен `~~`, это не ошибка проверки, но он попадает в еженедельную сводку неустойчивых ботов (issue «Неустойчивые боты — сводка CI», `tools/tests/flaky.py`) — такие боты чинят отдельной задачей. Прототип отдельно не гоняют: он только исходник релиза, все боты — на релизе (`affected.py` ботов только прототипа не запускает). Новый модуль релиза или файл сборки — сразу строка в `affected_map.txt` (иначе скрипт будет требовать полный регресс); правки прототипа для одного уровня — свой файл `rep_NN_<уровень>.py` со строкой `@level:ID` (не дописывать в чужой); новый бот уровня находится сам по `LV('id')`.

## Трейлер, сценарист, озвучка

- Трейлер снимается ботами из релизной сборки: `tools/video/` (`trailer.js` — кадры, `audio.js` — звук, `encode.sh` — MP4; см. `tools/video/README.md`). Готовое видео в git не кладётся.
- Тексты игры для сценариста: документы Word и снимки — `zlataya_cep/docs/script/`, инструменты — `tools/script/` (как вносить правки в игру — прототип, `rep_*.py`, модули, озвучка — `tools/script/README.md`). Первый круг правок внесён (отчёт — `pravki_final06.md`). Сейчас у сценариста `zlataya_cep_texts_final06_v2.docx` со снимком `texts_final06_v2.json` («Новый вариант» пуст); присланный документ читает `node tools/script/read_doc.js присланный.docx zlataya_cep/docs/script/texts_final06_v2.json правки.md > правки.json` (по номерам строк, против того снимка, с которого делался документ), вносит `node tools/script/apply_edits.js правки.json zlataya_cep/docs/script/texts_final06_v2.json --rev=$(git log -1 --format=%h -- zlataya_cep/docs/script/texts_final06_v2.json) --write` (коммит снимка: по нему правка находит своё место, даже если файлы с тех пор менялись).
- Озвучка реплик (final06): каталог `zlataya_cep/build/voice/lines.json` и записи `<id>.mp3` рядом; голоса генерируются моделью Eleven v4 в Higgsfield, записи готовит `node tools/voice/fetch.js` (см. `zlataya_cep/docs/09_final06.md`). Сборка встраивает записи в релиз и останавливается, если озвученной строки нет в игре.

## Конфликты при слиянии веток

- `zlataya_cep/zlataya_cep_final06.html` — не в git, конфликтов нет; после слияния исходников — `python3 zlataya_cep/build/build_final.py` (не коммитить).
- `zlataya_cep/build/voice/lines.json` — объединить записи обеих сторон (id уникальны по уровню: `5-1_091`, `5-B2_k01`, `p05a_hihi`); совпавший id — по смыслу. Сборка проверит, что каждая озвученная строка есть в игре. Файлы `.mp3` не конфликтуют.
- `tools/tests/bots/tfin_col.js` (эталон коллизий `RELEASE`) — взять обе стороны и пересчитать для изменённых уровней: `python3 tools/tests/col_update.py 2-3 3-1` (после правки геометрии уровня — так же); `regress_list*.txt` — объединить списки.
- `MAP.md` — автоматическую часть не сливать руками: после слияния `python3 tools/map.py`.
- `README.md`, документы — оставить записи обеих сторон (журнал изменений — файлы в `docs/changes/`, не конфликтуют); крупная задача — свой документ в `zlataya_cep/docs/`.
- `proto/*` — конфликт в одной части разбирать по смыслу, затем боты этого уровня (`affected.py` их найдёт). Ветка, начатая до разбивки, правила цельный `index.html`: при слиянии `main` взять её `index.html` (`git checkout --theirs`/`--ours` — версию ветки) и разрезать `python3 tools/proto.py split index.html`, затем `git rm --cached index.html` — правки лягут в свои части.
